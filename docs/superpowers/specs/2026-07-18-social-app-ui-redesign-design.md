# 遇见路得社交化应用 UI 重设计

日期：2026-07-18

## 目标

将登录后的应用从页面孤岛与表单后台，升级为“有秩序的关系动态平台”。整体借鉴 X 首页成熟的三栏信息架构、内容密度和即时反馈；不复用其品牌、文案或资产，也不把婚恋产品改造成无尽信息流。

设计必须同时达成：

- 让用户看见平台中正在发生的人、关系与成长，而非只面对任务列表。
- 让每个页面只有一个明确的主要行动，并提供自然的后续入口。
- 保持匿名推荐、双方心动后私信和资料逐步披露的安全边界。
- 在桌面和移动端使用同一语义与组件系统。

## 已确认的视觉方向

### 信息架构

桌面端采用固定三栏：

| 区域 | 职责 |
| --- | --- |
| 左栏 | 全局导航、主操作、当前用户入口。固定且不随内容变化。 |
| 中栏 | 当前页面的主内容流；包含页签、动态、候选、课程、讨论或会话。 |
| 右栏 | 与当前任务相关的推荐人物、小组、进度、上下文和安全提醒。 |

移动端隐藏左右辅助栏，保留页面标题、主内容和底部四项导航；消息和个人入口保留在顶部。

主导航固定为：首页、认识、成长、社区、消息；“我的”收纳在左栏底部头像菜单。当前项使用浅青绿色容器、深青色图标和文字，而不是仅改变文字颜色。

### 视觉语言

- 基底：近白和极浅青灰的页面底色；主体内容用白色表面与细分隔线组织。
- 主色：盟约蓝/青绿用于当前态、链接、主按钮和进度；暖珊瑚只用于关系或提醒的有限强调。
- 字体：重要标题使用中文衬线体；正文、元数据与控件使用系统无衬线体。
- 质感：使用 1px 柔和边框、8–16px 圆角、极浅阴影、选中态底色和短促状态过渡。禁止玻璃拟态、强渐变光球与过度投影。
- 图标：生产实现统一使用 Lucide；原型中出现的字符图标仅表达占位和层级。

### 交互反馈

- 主按钮具有明确填充、悬停提亮、按压缩放和加载/禁用状态。
- 次级操作使用轮廓按钮或文字按钮，不能与主行动竞争。
- 动态条目、人物行、候选卡和侧栏导航在悬停时出现浅背景反馈。
- 消息、心动、跳过、关注、保存等动作必须有即时局部状态，不刷新整页。
- 遵循 `prefers-reduced-motion`，动画仅用于状态改变和进入反馈。

## 页面方案

### 首页

中栏使用“为你 / 正在关注”页签和高质量动态流：

1. 轻量记录输入入口。
2. 今日认识候选摘要，附匹配解释与查看入口。
3. 社群讨论与继续学习动态。

右栏依次显示“今日值得认识”“值得关注的小组/共读”“正在讨论”。人物推荐必须使用匿名安全范围内的头像、短简介与单一行动，不显示敏感资料。

### 认识 / 匹配

中栏使用“今日精选 / 已表达心意”页签。每日最多三位匿名候选按流式条目呈现，每个条目包括：匿名视觉、地点范围、匹配等级、两到三条理由或一条沟通提醒，以及“心动 / 暂时跳过”。

右栏展示关系预备进度和近期心意；不泄露联系方式、精确年龄、完整教会名称、问卷答案或底线项。互相心动后引导进入消息页。

### 成长

中栏使用“为你继续 / 探索内容”页签，按继续课程、教材阅读、AI 咨询的优先级组织。内容项展示封面、类型、进度、预计时长与单一继续行动。

右栏提供本周学习计划和正在学习的同行者/小组；它是协作与计划的补充，不创建无限推荐流。

### 社区

中栏是一条高质量关系动态流，包含小组话题、成员分享、共读讨论和互动摘要。右栏包含关注小组和热门讨论。发布、评论、点赞、保存需要可访问名称和可恢复错误状态。

### 消息

桌面中栏改为会话列表 + 当前对话；右栏显示关系提醒、共同话题和隐私保护。消息气泡使用双方清晰区分的表面色，不依赖红绿区分状态。仅在互相心动后显示私信入口。

### 我的资料

中栏以个人头图、头像、简介、准备进度和“我看重的事”建立可信赖的人物档案。右栏管理资料披露、匹配偏好、账户和安全支持。所有敏感字段遵循既有资料可见性规则。

## 组件与数据边界

新增或统一的可复用组件：

- `AppShell`：三栏布局、响应式导航和页面标题。
- `FeedTabs`、`FeedItem`、`ReactionBar`：页面内内容流和局部反馈。
- `PersonRow`、`GroupRow`、`RecommendationCard`：推荐人物、组织与关系入口。
- `ProgressCard`、`SafetyNotice`、`EmptyState`、`ErrorState`：右栏状态与恢复路径。
- `MessageThread`、`ConversationList`：消息体验。

现有 API 和隐私资格判断保持不变。每日匹配接口上线后，再将 `RecommendationCard` 绑定到当日推荐快照；未完成问卷、资格不足、请求失败和候选为空均须有明确的非阻塞状态。

## 响应式与可访问性

- 桌面：至少 1024px 时启用三栏；中栏维持可阅读宽度，右栏 280–320px。
- 平板：导航压缩为图标栏，右栏仍可见或收为可展开面板。
- 移动：单内容列、顶部上下文、底部导航；不横向溢出。
- 所有图标按钮提供可访问名称；键盘焦点、选中页签、状态提示和错误文案可读。
- 颜色不是唯一状态表达方式；对比度达到 AA。

## 验收

1. 六个核心页面使用相同的导航、颜色、按钮、人物行和右栏容器规则。
2. 每页能在 360px、768px、1024px+ 断点稳定阅读和操作。
3. 匹配、私信和资料页不因新 UI 暴露任何受限资料。
4. 加载、空、错误、禁用和成功状态均有明确反馈。
5. 页面不使用装饰性卡片墙、随机动效、玻璃拟态或品牌仿制资产。

## 非目标

- 本轮不改变匹配算法、关系权限、课程数据结构或社区后端。
- 本轮不复制 X 的名称、图标、资产、文案或商业交互。
- 本轮不将所有内容强制改为公开动态；私信、隐私资料和安全流程继续受现有规则保护。
