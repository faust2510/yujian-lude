# 遇见路得桌面端与 X 移动端拆分设计

日期：2026-07-19

## 1. 已确认的产品方向

- 桌面端以 Figma `nvWK0aiQ0PRSHQJq64AfvT` 为唯一视觉基准，验收尺寸为 1440×1024，保持 236 / 900 / 304 三栏结构。
- 移动端不再使用该 Figma 文件中的移动稿。移动端直接采用 X/Twitter 的白底、黑字、蓝色强调、平铺时间线、细分割线、紧凑导航与详情页交互。
- 移动端选择“几乎 1:1 复制 X”的方向，不保留酒红色、奶油底色、大圆角卡片或后台表单式布局。
- 重构覆盖全部登录后路由，而不是只覆盖八个核心页面。
- 桌面端和移动端共享 API 数据、权限、业务动作与错误语义，但不共享会迫使移动端继承错误骨架的页面视图。

## 2. Git、worktree 与任务拆分

使用同一 Git 仓库，不创建两个独立仓库。

| 任务 | 分支 | 验收标准 | 禁止事项 |
| --- | --- | --- | --- |
| 桌面端 | `codex/twitter-desktop` | Figma 桌面稿，1440×1024 | 不修改或评价移动端视觉 |
| 移动端 | `codex/x-mobile` | X/Twitter 移动端，390×844 | 不修改桌面三栏几何与桌面视觉 |
| 整合发布 | `codex/twitter-release` | 桌面与移动双尺寸回归、生产部署、线上截图 | 两个实现任务完成前禁止部署 |

执行顺序：

1. 将当前实现和审查修复保存为不可部署的安全基线。
2. 桌面任务完成审查并冻结桌面基线。
3. 移动任务从冻结的桌面提交开始，建立独立 X 移动组件体系。
4. 当前协调任务整合结果，运行完整发布门槛并做线上双尺寸验收。

如果两个实现任务需要触碰同一个共享业务文件，桌面任务优先保持只读；共享业务修复由整合任务接收，避免并行冲突。

## 3. 移动端视觉系统

移动断点为 `max-width: 767px`，原生验收尺寸为 390×844。

核心令牌：

- 页面背景：`#FFFFFF`
- 主文字：`#0F1419`
- 次文字：`#536471`
- 分割线：`#EFF3F4`
- X 强调蓝：`#1D9BF0`
- 顶部栏：53px，粘性定位
- 底部主导航：53px，固定定位并处理安全区
- 列表与时间线：全宽平铺，使用 1px 分割线，不使用外层卡片
- 圆角只用于头像、媒体、胶囊按钮和必要的输入控件，不用于包裹整页内容

移动端主导航固定为：首页、认识、成长、社区、书信。资料、信仰测试、教材、AI、关系、会员、牧者、课程创作、管理与退出登录从头像抽屉或页面内入口到达。

## 4. 共享 X 移动组件

移动任务建立以下可复用组件，页面不得自行复制一套近似实现：

- `XMobileShell`：安全区、顶部栏、内容滚动区、底部导航和抽屉。
- `XMobileTopBar`：头像/返回键、标题、可选单一操作。
- `XMobileTabs`：X 式双栏或多栏标签与蓝色选中指示器。
- `XMobileTimelineRow`：头像、作者信息、正文、媒体区和操作栏。
- `XMobileListRow`：私信、通知、设置、关系记录与教材条目。
- `XMobileDetailHeader`：返回、标题、次级信息与右侧操作。
- `XMobileFormRow`：无卡片的标签、输入、错误和辅助文本。
- `XMobileActionBar`：回复、转发语义动作、喜欢、收藏与更多操作。
- `XMobileFab`：只在具有明确主要创建动作的页面展示。
- `XMobileDrawer`：次级路由、账号状态与退出登录。
- `XMobileEmptyState`、`XMobileErrorRow`、`XMobileSkeleton`：统一加载、空数据和重试状态。

页面容器继续负责请求、状态和动作；桌面视图与移动视图接收相同数据，分别渲染。不得通过单纯 CSS 换皮来保留错误的卡片 DOM。

## 5. 全部登录路由的移动映射

- `/`、`/community`、`/community/user/:userId`：X 时间线与用户时间线。
- `/match`：X 时间线式候选内容，可连续浏览全部候选；操作进入行级动作区。
- `/courses`、`/textbooks`、教材章节：X Explore/Lists 式平铺列表和阅读详情。
- `/chat`：X 私信列表；进入会话后使用独立详情页、返回栏和输入区，并隐藏底部导航。
- `/ai`：X/Grok 式对话页；咨询边界、历史和真人介入说明始终可滚动到达。
- `/profile`：X 个人主页；编辑资料进入 X 编辑资料式全屏表单。
- `/faith-test`、`/relationships`、`/vip`：X Settings 式列表、步骤与表单行。
- `/pastor`、`/course-authoring`、`/admin`：保持业务密度，但统一为 X 的顶部栏、标签、列表、表单与详情模式。

登录、注册、重置密码和验证邮箱不属于登录后壳层，但需单独检查 390px 下无溢出；本次不强制将其重构为 X 时间线页面。

## 6. 状态、错误与可访问性

- 保留现有 API 契约、权限门槛和业务错误，不伪造点赞数、审核状态、时间或信任徽章。
- 加载状态使用与最终结构同形的骨架；失败状态在对应列表位置提供清晰重试入口。
- 纯图标按钮必须有稳定的中文可访问名称；动态动作同时描述当前行为，例如“点赞/取消点赞”。
- 触控目标不小于 44×44px；固定底栏不得遮挡正文、输入区或浏览器安全区。
- 对话、抽屉、标签和详情切换需要键盘焦点与返回路径。

## 7. 验收与发布门槛

桌面任务：

- 1440×1024 对照 Figma 桌面稿。
- 三栏宽度、导航、内容密度、右栏和八个核心路由截图回归。

移动任务：

- 390×844 全部登录路由自动巡检。
- 每页 `documentElement.scrollWidth === clientWidth`，明确的横向轮播除外。
- 顶栏、底栏、抽屉、标签、列表/详情切换、表单和主要动作均需真实交互证明。
- 对首页、认识、成长、社区、书信、AI、资料、会员至少保存一张代表截图，并与已确认的 X 移动视觉基准逐项对照。

整合发布任务：

- 前端测试、lint、build，后端单测，fresh DB 迁移、MVP 与真实多用户流程全部通过。
- 本地 1440×1024 和 390×844 截图通过后才能部署。
- 生产环境必须重新检查健康接口、登录、全部核心路由，并保存线上桌面与移动截图。
- 未完成线上截图前不得宣称任务完成。

## 8. 明确不做

- 不拆成两个独立 Git 仓库。
- 不把 Figma 错误移动稿继续作为参考。
- 不在桌面任务中顺手修移动端，也不在移动任务中重绘桌面端。
- 不部署任何单独实现分支。
- 不把测试截图、浏览器状态或可视化临时文件提交到产品源码。
