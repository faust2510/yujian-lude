# 遇见路得 UI 基础与应用骨架设计

日期：2026-07-13

## 目标

将“遇见路得”从功能入口平铺的后台式界面，重构为移动端优先、层级清楚、温暖可信的婚恋成长产品。第一阶段只建立后续页面共用的 UI 基础、导航骨架与动态首页，不修改后端 API、业务资格判断或数据库结构。

整体参考方向已经确认：

- SALT：基督信仰自然融入品牌、强识别字体、真实关系叙事、目的明确的横向动效。
- Hinge：真人场景、克制留白、每屏只讲一件事、滚动与手写强调动效。
- Circle：社区、课程、活动与聊天归入少数主空间的信息架构。
- Readwise Reader：沉浸式阅读、目录与正文的稳定分栏、阅读进度可见。
- shadcn/ui：组件、状态、表单、导航、反馈与可访问性的实现基础。

## 范围

第一阶段包含：

1. 在现有 React 19 + Vite + JavaScript 项目中接入 Tailwind 与 shadcn/ui。
2. 建立品牌语义色、字体、圆角、阴影、间距与动效令牌。
3. 重构登录后应用骨架：桌面侧栏、移动端顶部栏与底部导航。
4. 将当前 11 个同级入口收敛为 4 个主空间和 1 个用户入口。
5. 重构 `/app` 首页，去除重复任务与无意义卡片堆叠。
6. 提供统一的加载、空状态、错误、徽章、进度和提示组件用法。
7. 保持现有 URL 可访问，避免一次性路由迁移造成回归。

第一阶段不包含：

- 重写匹配算法、关系确认、课程、教材、社区或私信后端。
- 新增照片上传、实时 WebSocket、支付或新的数据库字段。
- 完整重做公开宣传首页。
- 将所有现有页面一次性迁移为 shadcn。

## 产品结构

### 主导航

| 主空间 | 核心任务 | 现有入口 |
|---|---|---|
| 首页 | 今日最重要行动、资格进度、继续上次任务 | 个人中心、签到、积分摘要 |
| 认识 | 找到候选人、沟通、确认关系 | 匹配、私信、关系 |
| 成长 | 完成装备、阅读教材、获得辅导 | 课程、教材、AI 咨询 |
| 社区 | 动态、小组、活动与成员互动 | 社群 |
| 我的 | 身份资料、信仰档案、测试、背书、套餐、退出 | 完善资料、信仰测试、套餐 |

桌面端使用固定侧栏。一级导航只显示“首页、认识、成长、社区”；侧栏底部显示用户头像与菜单，“我的”内容从该菜单进入。消息作为全局图标保留未读入口，但私信页面仍归属“认识”。

移动端使用顶部品牌栏与底部四项导航。顶部栏放消息和头像；底部导航只放首页、认识、成长、社区。任何受保护页面都必须能在两步内回到对应主空间。

### 路由策略

第一阶段不改变现有路由，只改变导航归属：

| 现有路由 | 导航归属 |
|---|---|
| `/app` | 首页 |
| `/app/match`、`/app/chat`、`/app/relationships` | 认识 |
| `/app/courses`、`/app/textbooks/*`、`/app/ai` | 成长 |
| `/app/community*` | 社区 |
| `/app/profile`、`/app/faith-test`、`/app/vip` | 我的 |
| `/app/admin` | 仅管理员用户菜单 |

后续阶段可以为主空间增加聚合页，但旧 URL 必须保留或重定向，外部链接和刷新行为不能失效。

## 视觉系统

### 风格

登录后应用不是营销落地页。它采用 SALT/Hinge 的品牌气质，但保持安静、任务导向和可长期使用：

- 大面积暖白背景与真实内容留白。
- 标题使用中文衬线体，控制在页面级标题与重要数字。
- 正文和控件使用系统无衬线体。
- 避免整页卡片墙；只为独立、可操作的对象使用 Card。
- 不使用紫色渐变、玻璃拟态、装饰性光球、假统计面板或 emoji 图标堆叠。
- 图标统一使用项目配置的 Lucide 图标。

### 语义色

| 令牌 | 用途 | 方向 |
|---|---|---|
| background | 全局底色 | 暖白 |
| foreground | 主文字 | 近黑暖灰 |
| primary | 主操作、选中导航 | 清晰的盟约蓝 |
| accent | 温暖强调、品牌细节 | 克制珊瑚红 |
| secondary | 次级表面 | 中性浅灰 |
| success | 已完成与安全状态 | 深绿 |
| destructive | 风险与删除 | 稳定红色 |
| border/input/ring | 分隔、表单、焦点 | 中性暖灰与主色焦点 |

所有页面使用语义类，不直接散落原始色值。品牌颜色通过全局 CSS 变量定义，组件优先使用 shadcn 内置 variant。

### 尺寸与层级

- 页面 H1：28-32px，单页最多一个。
- 区域标题：18-22px。
- 正文：14-16px，阅读正文使用更宽松行高。
- 按钮：默认高度稳定，图标按钮使用标准正方形尺寸。
- 卡片圆角不超过 8px；抽屉、对话框遵循 shadcn 默认结构。
- 主内容宽度按页面类型变化，首页保持可扫描，阅读器允许更宽分栏。

## shadcn 采用方式

### 原则

shadcn 作为源代码级设计系统，而不是零散组件集合。项目采用 JavaScript 输出，保持现有 Vite 与 React Router 架构，不为此次重构切换 TypeScript 或框架。

初始配置采用 **Nova preset + Radix base + Lucide icons**。Nova 的紧凑层级适合长期使用的应用界面；Radix 的组件生态与 React Router 组合方式成熟；Lucide 用于替换现有 emoji 和手写操作图标。初始化同时建立 `@/*` 导入别名和 Tailwind v4 全局样式入口。

优先组件：

- 骨架：Sidebar、NavigationMenu、Sheet、Drawer、DropdownMenu、Avatar、Tooltip。
- 状态：Badge、Progress、Alert、Skeleton、Spinner、Empty、Sonner。
- 内容：Card、Separator、Tabs、Accordion、Collapsible、ScrollArea。
- 表单：Field、FieldGroup、Input、Textarea、Select、Checkbox、RadioGroup、ToggleGroup。
- 消息：MessageScroller、Message、Bubble、Marker；在私信阶段替换手写气泡与滚动逻辑。

组件必须遵守 shadcn 组合规则：Card 使用完整分区，Dialog/Sheet/Drawer 有标题，Avatar 有 fallback，菜单项位于 Group 内，表单使用 Field，状态使用 Badge/Alert/Empty，不重复手写已有组件。

### 渐进迁移

1. 初始化 Tailwind、shadcn 配置、别名、工具函数与主题令牌。
2. 新建应用骨架和共享组件，先迁移 `/app` 首页。
3. 后续按“认识 -> 成长 -> 社区 -> 我的 -> 公开首页”的顺序迁移页面。

旧 CSS 在迁移期间保留，但新组件不得继续添加大段内联 style。每迁移一个页面，删除该页面确认不再使用的旧样式，避免长期双系统。

## 首页设计

### 未完成入池资格

首页首屏只回答“我下一步该做什么”：

1. 简短问候与当前状态。
2. 一个主行动区域，显示最优先的未完成任务及 CTA。
3. 紧凑资格进度，默认只显示完成数量，可展开查看五项明细。
4. “继续成长”和“社区动态”作为次要区域。
5. 积分与签到缩为次级操作，不再占据首屏半壁空间。

### 已进入匹配池

首页改为关系旅程总览：

1. 今日建议：查看新候选、继续课程或参与社区，三者只选一个主 CTA。
2. 认识状态：新候选、待回复意向或当前关系状态。
3. 成长进度：最近课程或教材的继续阅读入口。
4. 社区摘要：最多三条有意义动态。
5. 签到放在头像菜单或紧凑工具区，成功后使用 toast 和即时余额更新。

不再同时显示“入池任务中心”和“下一步做什么”两套重复列表。

## 动效

全站最多使用三类动效，并尊重 `prefers-reduced-motion`：

1. 页面与内容进入：150-240ms 的淡入和轻微位移，仅用于路由或区域首次出现。
2. 状态变化：导航选中、进度、Accordion/Drawer 展开和按钮反馈，使用短促过渡。
3. 品牌叙事：仅公开首页或空状态使用真人媒体、横向文字轨道或轻量滚动强调；登录后应用不使用持续自动播放的装饰动画。

不使用随机漂浮、连续缩放、背景光球或会干扰阅读的视差。

## 可访问性与响应式

- 360px 宽度下必须存在可用底部导航，正文与按钮不横向溢出。
- 768px 以下桌面侧栏替换为移动导航，而不是简单隐藏。
- 所有图标按钮有可访问名称和 Tooltip。
- 当前导航项使用语义化 active 状态。
- 焦点环清晰，表单错误同时提供文字与 `aria-invalid`。
- Drawer、Sheet、Dialog 均包含标题。
- 动效在减少动态偏好下关闭或显著简化。

## 数据与错误处理

本阶段复用现有 API。首页并行读取积分与匹配资格时：

- 单个请求失败不阻断整个首页。
- 使用 Skeleton 保持布局稳定。
- 可恢复错误使用 Alert 与重试按钮。
- 签到冲突显示服务器错误，不虚假增加积分。
- 空数据使用 Empty，不显示伪造统计。

## 测试与验收

### 自动化

- 保持现有前端测试、lint 和 build 全部通过。
- 增加导航配置测试：每个旧路由归属正确主空间。
- 增加响应式结构测试：移动端导航存在，桌面侧栏存在。
- 增加首页状态测试：未入池与已入池不会同时显示重复任务列表。

### Playwright 视觉验收

桌面：1440x900、1280x800。

移动：390x844、360x800。

检查：

- 无横向溢出、遮挡和文字截断。
- 移动端可从任何主页面切换四个主空间。
- 页面加载与错误状态不会导致布局大幅跳动。
- 导航、头像菜单、Sheet/Drawer、进度展开均可键盘操作。
- 首页首屏只有一个明确主行动。

## 后续阶段

1. 认识：将匹配改为 Hinge 式单候选聚焦体验，关系与私信归入同一旅程；优先修复手机端 Chat 固定双栏、软键盘遮挡和缺少会话返回的问题。
2. 成长：课程使用 Accordion/Tabs，教材阅读采用 Readwise 式目录与正文分栏。
3. 社区：采用 Circle 式“动态、小组、活动”空间结构，并补齐安全私信边界。
4. 我的：资料、信仰、背书、安全和套餐重新分组。
5. 公开首页：使用真实人物媒体和 SALT/Hinge 式品牌叙事，保持 `/app` 为实际产品入口。

## 成功定义

第一阶段完成后，用户在桌面和手机上都能清楚理解遇见路得的四个主空间；首页只呈现当前最重要的行动；现有业务路由和数据行为不变；新 UI 具备一致的 shadcn 组件、语义颜色、加载反馈和可访问性基础，为后续页面迁移提供稳定模板。
